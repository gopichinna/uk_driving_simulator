## 1. What this is
**L to Local** (tagline **"Keep Left"**) is a mobile driving game (Android + iOS) that teaches **UK road rules by doing**. Players drive low-poly 3D scenarios and get instant, explained feedback linked to the Highway Code. The target user is a newcomer to the UK, or a UK learner, aged **18+**. Launch market: **Great Britain** only. Price: **£14.99** one-off; the first 3 lessons are free.

| Decided | Value |
|---|---|
| Engine | **Unity 6** (currently 6.6, `6000.6.10f1`; move to 6.7 LTS before the vertical slice), URP, IL2CPP, C# |
| Core | **Engine-free C#** (`core/`, .NET Standard 2.1, C# 9), with no `UnityEngine` references (CI enforces this) |
| Content pipeline | **Python** (`pipeline/`); map data from OpenStreetMap (ODbL) |
| Backend (later) | Firebase + RevenueCat |
| Language | English only for v1 (CEFR B1 plain English) |
| Prototype city | Wolverhampton city centre |

The full planning set is in `docs/00`–`07`. The rules catalogue, with every rule's Highway Code source, is `docs/02-rules-catalogue.md`.

## 3. How to build and test
- **Core (C#)**: `cd core && dotnet test`. Needs the .NET SDK (8+ works; CI uses 11). The tests must stay green.
- **Pipeline (Python)**: `cd pipeline && python -m pytest` (once it exists; Python 3.12+).
- **Unity**: needs macOS + Unity 6.6. Scenes and the APK are built in batch mode:
  - `Unity -batchmode -nographics -projectPath unity -buildTarget Android -executeMethod LToLocal.EditorTools.ProjectSetup.SetupAll -quit`
  - `... -executeMethod LToLocal.EditorTools.ProjectSetup.BuildAndroid -quit` writes `unity/Builds/Android/LToLocal.apk`
  - `... -executeMethod LToLocal.EditorTools.PreviewRenderer.RenderViews -quit` writes preview PNGs to `unity/Builds/Previews/`
- CI: `.github/workflows/core-tests.yml` runs `dotnet test` and blocks `UnityEngine` in `core/`.

## 4. Rules for contributors (humans and agents)
1. **Never invent road rules.** Every rule needs a GOV.UK source (Highway Code rule number + URL) in `docs/02-rules-catalogue.md`, and later in `content/countries/gb/rules.yaml`. Mark anything you could not check as `UNVERIFIED`.
2. Don't use DVSA-licensed material (hazard-perception clips, theory question banks).
3. **Country-agnostic code.** Code talks in **nearside/offside** and **near turn/far turn**; the country pack maps those to left/right. GB = left-hand traffic, clockwise roundabouts.
4. **Engine-free core.** Simulation and rules logic go in `core/`, with tests. Unity only displays and handles input.
5. Every rule needs fixtures (pass / minor / serious-or-dangerous) in the tests.
6. Plain English (CEFR B1) for player-facing messages; one idea per sentence.
7. Player feedback design (decided after play-tests): **no "observation" busywork**. Players are not asked to tap mirrors or hold shoulder-check buttons; the game judges outcomes (e.g. "a car was in your blind spot").
8. AI traffic keeps a **3-second** following gap. The player rule is the Highway Code's **2-second** minimum (rule 126).
9. OSM data is ODbL: keep the attribution "© OpenStreetMap contributors"; derived road packs are ODbL too.
10. **Stay in your lane.** Only edit the files your branch owns (`docs/08-parallel-work-plan.md` §3). If you need a change in someone else's area, write it under "Requests to the other branch" in your task file.
11. Commit messages: imperative summary line, then a short body explaining why.
